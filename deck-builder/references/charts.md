# 圖表：原生、可在 PowerPoint 編輯

圖表是**真正的 `c:chart` 部件**，資料存在內嵌的 Excel 工作表裡。使用者在 PowerPoint 裡
點下去可以改數字、換圖表類型、拉圖例。**不是圖片**——圖片對下一季要更新這份簡報的人來說
是死路。

規則來自 `dataviz` skill 的方法，但色票是針對**這個樣板的實際底色**重新推導、並用它的
`scripts/validate_palette.js` 實測過的。下面每一個數字都是指令的輸出，不是估的。

---

## 一、先選形式，不要先選顏色

問一句話：**這個數字的工作是什麼？**

| 資料的工作 | 形式 | `form` | 什麼時候不要用 |
|---|---|---|---|
| 比大小（類別名字長） | 橫向長條 | `bar` | 類別超過 12 個 |
| 比大小（少數幾個期間） | 直向長條 | `column` | 只有一個類別——那是一個數字 |
| 一個數字是重點，其他是背景 | 長條＋強調色 | `column` ＋ `"colors": "emphasis"` | 沒有明確的主角 |
| 隨時間變化 | 折線 | `line` / `line-markers` | 少於 4 個點 |
| 組成比例隨時間 | 堆疊長條 | `stacked-column` | 超過 4 段 |
| 組成比例（單一時點） | 圓餅 | `pie` | **少於 3 片**（那是兩個數字）；超過 5 片 |
| 兩個量的關聯 | 散佈 | `scatter` | 超過 3 個數列（見下方 all-pairs） |

**有時答案是「不要圖表」。** 一個數字就是一個數字——放進標題，或當成大字。
一根柱子的長條圖、兩片的圓餅，都會被 `build_deck.py` 擋下來或警告。

**永遠不做雙 Y 軸。** 這裡是結構上做不到的：一張圖一個值軸。兩個量級不同的指標 →
兩張圖，或都換算成指數。

## 二、顏色按它做的工作分派

`"colors"` 的六個值，各有一條規則：

| `colors` | 用在 | 規則 |
|---|---|---|
| `categorical`（預設） | 身分（產品、團隊、地區） | 固定槽位順序，**永不循環** |
| `sequential` | 量的大小 | 單一色相，淺 → 深 |
| `ordinal` | 順序（漏斗階段、級距） | 同上——順序要看得出來 |
| `diverging` | 極性（正 / 負） | 兩個色相＋**中性灰**中點 |
| `emphasis` | 一個主角 | 主角品牌藍，其餘中性灰 |
| `status` | 狀態 | 語意固定，且**永不只靠顏色** |

**類別是名目還是順序？** 交換順序會改變意思（S/M/L、漏斗階段）就是 `ordinal`，
用單一色相深淺。交換不會改變意思（產品名、團隊）就是名目——單一數列時**每根柱子都用
槽位 1 的同一個藍**，因為對名目類別套用深淺會暗示一個不存在的順序。

### 類別色票（8 個固定槽位）

| 槽 | 色 | 白底對比 |
|---|---|---|
| 1 | `#0d63ba` 品牌藍 | 5.98:1 |
| 2 | `#eb6834` 橘 | 3.20:1 |
| 3 | `#12a06d` 綠 | 3.35:1 |
| 4 | `#c74d7c` 洋紅 | 4.39:1 |
| 5 | `#4a3aa7` 紫 | 8.56:1 |
| 6 | `#b87c00` 赭 | 3.55:1 |
| 7 | `#008300` 深綠 | 4.95:1 |
| 8 | `#e34948` 紅 | 3.95:1 |

實測（dataviz 的驗證器，不是目測）：

```bash
node <dataviz>/scripts/validate_palette.js \
  "#0d63ba,#eb6834,#12a06d,#c74d7c,#4a3aa7,#b87c00,#008300,#e34948" \
  --mode light --surface "#ffffff"
```

```
[PASS] 明度帶      8 個都在 L 0.43–0.77
[PASS] 彩度下限    8 個都 >= 0.1
[PASS] 色盲區辨    最差相鄰 #12a06d↔#eb6834 ΔE 8.4（protan）
[PASS] 正常視覺    最差相鄰 ΔE 18.3
[PASS] 底色對比    8 個都 >= 3:1
→ ALL CHECKS PASS
```

**第 9 個數列不存在。** 色相永不循環——第 9 個會和第 1 個分不出來。折進「其他」，
或改成小倍數圖。`build_deck.py` 會直接報錯。

### `--pairs all`：散佈圖只能 3 個數列

長條與折線只需要**相鄰**槽位可分辨（讀者比較的是鄰居）。散佈圖和泡泡圖不是——每一點都
和其他所有點比，所以要過 all-pairs。實測只有前 3 槽過得了：

```
前 3 個，all pairs → ALL CHECKS PASS（最差 ΔE 8.4 protan / 24.4 正常）
前 4 個，all pairs → FAIL：#b87c00 ↔ #eb6834 ΔE 2.3（protan）、10.7（正常視覺）
```

超過 3 個會警告，並告訴你是哪一對撞在一起。

### 序數／量值色階

`#86b6ef → #6da7ec → #3987e5 → #0d63ba → #0a4a8c`

淺端 `#86b6ef` 在白底是 **2.11:1**，達到色階淺端 ≥ 2:1 的門檻。

**把類別驗證器拿去跑色階會 FAIL，那是設計上的。** dataviz 自己寫在
`color-formula.md`：色階跨越整個明度帶、相鄰步階本來就接近，「這是預期的，不是真的失敗；
不要為了滿足它去改一個好的色階」。色階真正要檢查的是明度單調遞增，以及淺端還看得見。

### 極性色階

`#b3401c → #e8825c → #d8d8d8 → #6da7ec → #0d63ba`

中點是**中性灰** `#d8d8d8`。中點放色相會讀成第三個類別，而不是「沒有變化」。

### 狀態色（語意保留）

`good #008300` · `warning #b87c00` · `serious #eb6834` · `critical #e34948`

**永不當成「第 4 個數列」用**，而且**永不只靠顏色**——類別名稱本身要說出狀態，顏色只是
加強。

## 三、深底版面不放圖表（實測結論）

**`Content Heading Dark` 只放文字。** 這不是偏好，是量出來的：

- dataviz 的深色步階放在導覽藍 `#0b539d` 上，**8 個槽位全部低於 3:1**。
- 亮色步階拉不上去：`#eb6834` L=0.671、`#eda100` L=0.764、`#4a3aa7` L=0.433，
  **FAIL 深色模式的明度帶**（0.48–0.67）。
- 手動提亮的版本兩邊都掛：`#86b6ef` C=0.097、`#f0a8c2` C=0.090，**低於彩度下限**，
  顏色開始讀成灰色、不再承擔身分。
- 唯一過得了的組合是 ≤3 個深色步階，但**每個標記都只有約 2:1**——那已經不是可辨識的標記。

深底本來就是給一句重話用的，不是給資料用的。`build_deck.py` 放圖表在深底會警告，
`verify_deck.py` 會報**錯誤**。

## 四、pptx 做不到的兩件事（明說，不默默丟掉）

dataviz 的規格有兩項在 .pptx 裡無法實作：

1. **沒有圓角資料端。** DrawingML 的圖表數列沒有圓角半徑可設，所以長條是方角。
   （畫一個圓角矩形就不是圖表了，那是圖形。）
2. **沒有 hover 層。** .pptx 沒有 hover。所以身分改為靠**圖例**與**選擇性直接標註**
   承擔——這也是為什麼這兩項在這裡是預設開啟的。

可以做到而且預設有做的：2pt 線寬、≥8px 標記加 2px 底色描邊環（重疊的點還數得出來）、
0.75pt 實線格線（永不虛線）、隱藏值軸線、去掉刻度、標記無外框、長條間距 80%。

## 五、標註：不要每個點都標數字

**每個點都標數字，就是一張多繞了幾步的表格。** 標首、末、峰值通常就是全部的故事，
其餘讀格線。

```json
"label_points": [0, 3, -1]          // 索引，負數從尾算
"label_points": {"series": 1, "points": [0, -1]}
"label_points": "all"               // 會警告
```

`≥ 2` 個數列一定有圖例；只有 1 個數列則沒有——標題已經講了它是什麼。

## 六、spec 欄位

```json
{
  "layout": "Content Heading",
  "title": "8/5 是最忙的一天",
  "chart": {
    "form": "column",
    "categories": ["8/4", "8/5", "8/6"],
    "series": [{"name": "模型呼叫次數", "values": [421, 593, 55]}],
    "colors": "emphasis",
    "emphasize": 1,
    "label_points": [0, 1, 2],
    "number_format": "#,##0",
    "axis_format": "#,##0,,\"M\"",
    "max_scale": 700,
    "box": [0.92, 1.70, 11.50, 4.75]
  }
}
```

| 欄位 | 說明 |
|---|---|
| `form` | 見第一節 |
| `categories` | 類別軸標籤；`scatter` 不用 |
| `series` | `[{name, values}]`；`scatter` 的 `values` 是 `[[x, y], …]` |
| `colors` | 見第二節，預設 `categorical` |
| `emphasize` | `colors: "emphasis"` 用，要強調的點索引（可給陣列） |
| `status` | `colors: "status"` 用，每個點一個角色名 |
| `label_points` | 見第五節 |
| `number_format` | 資料標註的格式，Excel 格式碼 |
| `axis_format` | 值軸刻度的格式 |
| `max_scale` | 值軸上限，需要跨頁比較時才設 |
| `box` | `[left, top, width, height]` 英寸，覆寫預設位置 |

**圖表可以和 bullets 同頁**，這是唯一允許的組合：文字講「所以呢」，圖表是證據。
文字佔左半、圖表佔右半，自動配置。其他任何組合（圖表＋表格、圖表＋圖片）都會報錯。

推薦風格另有 `"layout": "chart"`（滿版）與 `"layout": "chart-right"`（左文右圖）。

## 七、驗證器會檢查什麼

`verify_deck.py` 對每張有圖表的頁面：

- 色值**不在**已驗證色票內 → 警告。色票的色盲區辨是當成**一組**量的，換掉一個色相就
  破壞了對其他色相的保證。
- 數列超過 8 個 → 錯誤。
- `≥ 2` 個數列卻沒有圖例 → 警告（身分會變成只靠顏色，而 pptx 沒有 hover 可退）。
- 1 個數列卻有圖例 → 警告。
- 圖表裡有中文卻沒有 `a:ea` 字體 → 警告。python-pptx 的 `font.name` **只寫 `a:latin`**，
  圖表部件有自己的文字屬性，所以這個坑在圖表裡會再出現一次。
- 圖表放在深底 → **錯誤**（見第三節）。
