# 版面速查（Layout Reference）

每個版面的視覺結構、支援的內容欄位、以及使用時機。
兩種風格都在這裡；選版面的決策矩陣在最後。

## CSI 樣板（`style: "csi"` · 舊名 `company`）

深底版面（●）的 builder 自加文字框一律白色；`verify_deck.py` 會對照真實背景量對比度。

### content（標準內容）— Composition Variant 系統

`content` 支援 `:standard`、`:editorial`、`:spotlight`、`:diagram`、`:data-story` composition variants。以下先列基本結構，再列各 variant。

```
┌─────────────────────────────────────────────────┐
│ ┌──────────────────────────────────────────────┐ │
│ │  標題  28pt bold                              │ │
│ └──────────────────────────────────────────────┘ │
│  ────────────── ← 藍線 2.2"                      │
│ ┌──────────────────────────────────────────────┐ │
│ │  ● 要點一  18pt                               │ │
│ │    ○ 第二層  16pt                             │ │
│ │  ● 要點二                                    │ │
│ │               或  段落文字  或  表格  或  圖表 │ │
│ └──────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────┘
```

| 欄位 | 說明 |
|---|---|
| `title` | 標題（28pt bold，`#13182c`） |
| `bullets` | 要點（18pt，最多 ~6 條） |
| `paragraphs` | 敘述文字 |
| `table` | 表格 |
| `chart` | 圖表（可與 bullets 同頁） |
| `cards` | 卡片格（可加 variant，見下方） |
| `image` | 圖片 |
| `notes` | 講者備註 |


#### content Composition Variants

`content` 是彈性內容畫布，不應被視為固定的「標題＋條列」模板。可依內容目的指定 composition variant；若未指定則使用 `content:standard`。

##### `content:standard` — 一般內容

適合一般 supporting information、短條列、段落、表格或單純圖表。

```
┌─────────────────────────────────────────────────┐
│ TITLE / CONCLUSION                              │
│ ──────────────                                  │
│                                                 │
│  ● supporting point                             │
│  ● supporting point                             │
│  ● supporting point                             │
│                                                 │
└─────────────────────────────────────────────────┘
```

##### `content:editorial` — 編輯式非對稱構圖

一個論點明顯比其他資訊重要時使用。主文約佔左側 65%，右側為次要 insight。

**欄位約定：** `subtitle`（或第一條 bullet／paragraph）＝左側主文；其餘 bullets／paragraphs＝右側支援。

```
┌─────────────────────────────────────────────────┐
│ TITLE / CONCLUSION                              │
│                                                 │
│ ┌───────────────────────────┐ ┌───────────────┐ │
│ │ Primary narrative         │ │ Secondary     │ │
│ │ (subtitle or 1st line)    │ │ bullets       │ │
│ │                           │ │               │ │
│ └───────────────────────────┘ └───────────────┘ │
└─────────────────────────────────────────────────┘
```

##### `content:spotlight` — 單一焦點

適合一個概念或主張需要明顯主導視覺，但又不適合 `big_number` / `quote` / `statement` 的頁面。

**欄位約定：** `subtitle`（或第一條 line）＝置中焦點句；其餘＝右下角短說明。

```
┌─────────────────────────────────────────────────┐
│ TITLE                                           │
│                                                 │
│        DOMINANT STATEMENT (subtitle / 1st)      │
│                                                 │
│                         supporting explanation  │
└─────────────────────────────────────────────────┘
```

##### `content:diagram` — 關係 / 架構圖

系統、架構、角色關係、概念模型優先使用。關係比順序重要時，不要硬塞進等尺寸 cards。

**必填：** `cards` 陣列。第一項＝中心（hub），其後最多 4 項＝spokes（下方橫列）。
不是自由繪圖——builder 用卡片 primitive 排成 hub-and-spoke。

```
┌─────────────────────────────────────────────────┐
│ TITLE / CONCLUSION                              │
│                                                 │
│                  ┌─────────┐                    │
│                  │ cards[0]│  ← hub (featured)  │
│                  └────┬────┘                    │
│               ┌───────┼───────┐                │
│            cards[1] cards[2] cards[3]           │
└─────────────────────────────────────────────────┘
```

##### `content:data-story` — 圖表敘事

圖表是視覺主角，文字只負責告訴觀眾「要看什麼」與「代表什麼」。

**必填：** `chart`。左側 insight 來自 `subtitle`（若有）＋ `bullets`／`paragraphs`。

```
┌─────────────────────────────────────────────────┐
│ CONCLUSION TITLE                                │
│                                                 │
│ ┌────────────────────────────┐ ┌──────────────┐ │
│ │ Key insight                │ │              │ │
│ │ (subtitle + lines)         │ │    CHART     │ │
│ │                            │ │              │ │
│ └────────────────────────────┘ └──────────────┘ │
└─────────────────────────────────────────────────┘
```

**共同規則：**
- Variant 是 composition pattern，不是新的 PowerPoint master layout。
- 同一 variant 再次使用時，應依內容比例與前後頁關係調整，不得機械複製。
- 一頁應有一個 dominant focal point。
- 不要為了填滿空白而加入裝飾；whitespace 是設計元素。
- 未知的 `content:*` variant 會走一般 `content` 路徑（可能不符合預期）——只用上方列出的名稱。

### cards — Variant 系統

`layout` 欄位本身決定卡片格的**網格形狀**，個別卡片的**繪製風格**用冒號 variant 切換。

#### 網格 Variants（`cards:2-col`、`cards:3-col`、`cards:4-grid`）

```
cards:2-col（2 欄單列）
┌──────────────────┐  ┌──────────────────┐
│ ▬ 品牌色條        │  │ ▬                │
│  標題            │  │  標題            │
│  內文            │  │  內文            │
└──────────────────┘  └──────────────────┘

cards:3-col（3 欄單列）
┌─────────┐  ┌─────────┐  ┌─────────┐
│ ▬       │  │ ▬       │  │ ▬       │
│  標題   │  │  標題   │  │  標題   │
│  內文   │  │  內文   │  │  內文   │
└─────────┘  └─────────┘  └─────────┘

cards:4-grid（2×2 方格）
┌──────────────────┐  ┌──────────────────┐
│ ▬                │  │ ▬                │
│  標題  內文      │  │  標題  內文      │
└──────────────────┘  └──────────────────┘
┌──────────────────┐  ┌──────────────────┐
│ ▬                │  │ ▬                │
│  標題  內文      │  │  標題  內文      │
└──────────────────┘  └──────────────────┘
```

省略 variant 時自動依數量決定網格（2–3 → 單列，4 → 2×2，5–6 → 3×2）。

#### 繪製風格 Variants（`cards:icon`、`cards:number`、`cards:image`）

```
cards:icon（icon 置中於卡片頂部）
┌──────────────────┐
│ ▬ 品牌色條        │
│                  │
│     [  ICON  ]   │  ← 大 icon 置中
│                  │
│  標題（置中）     │
│  內文（置中）     │
└──────────────────┘

cards:number（大序號取代 icon）
┌──────────────────┐
```

#### 非對稱卡片 Variants（`cards:bento`、`cards:featured`）

等尺寸卡片只適合「每個概念真的同等重要」的情況。若內容有自然主次，優先使用非對稱構圖。

##### `cards:bento`

一個 primary concept + 2–4 個 supporting concepts。主卡應明顯大於其他卡片。

```
┌──────────────────────────┐  ┌───────────────┐
│                          │  │      B        │
│          A               │  ├───────────────┤
│       PRIMARY            │  │      C        │
│                          │  │               │
└──────────────────────────┘  └───────────────┘
```

適合：核心能力＋支援能力、主要問題＋次要問題、主產品＋周邊模組。

##### `cards:featured`

第一項是明確主角，其餘項目為 supporting evidence / dimensions。

```
┌─────────────────────────────────────────────┐
│ 01                                          │
│ PRIMARY INSIGHT                             │
│ Larger supporting content                  │
└─────────────────────────────────────────────┘

   02 Supporting              03 Supporting
```

適合：P0 + P1/P2、主要建議＋兩項支援理由、核心功能＋次要功能。

**卡片構圖規則：**
- 不要因為內容有 3–4 項就自動選 cards。
- 等尺寸 grid 只代表 equal importance。
- 若一項資訊更重要，使用 `bento` / `featured` 或改用 `content:editorial`。
- 避免連續多頁 cards；cards 不應成為整份 deck 的預設語言。
- Card 內文字應短；若每張 card 都需要長段落，改用其他 layout。

### dark（深底投影片）

任何版面都可以加 `dark: true` 變成深底版本。這不是一個獨立的 `layout` 值，而是一個**每頁開關**。

```
dark: true（全版深底）
┌─────────────────────────────────────────────────┐
│  ████████████████████████████████████████████   │  ← 品牌主色 #0d63ba 全版
│  ████████████████████████████████████████████   │
│  ──────────── ← 淺藍色線 #6ba5e0                │
│  標題  白色                                      │
│  ● 要點（白色）                                  │
│  ● 要點                                         │
│                         頁碼  淺灰               │
│  ████████████████████████████████████████████   │
└─────────────────────────────────────────────────┘
```

- 背景：`#0d63ba`（品牌主色）全版矩形
- 標題／內文：白色 `#ffffff`
- 次要文字（頁碼、副標）：`#e7e6e6`
- 強調線 / 品牌條：`#6ba5e0`
- 深底頁**不放圖表**（`verify_deck.py` 硬錯誤）

**深淺混用規則：** 未指定時 builder 依判斷自行混入深底版面（適合段落分隔、關鍵數字、最終請求）。若需要全淺或全深，在 frontmatter 設 `dark: false` 或 `dark: true`；對個別投影片設 `dark: true` 可覆寫全局預設。

#### Image composition rules

Builder 的 `image:right`／`image:left` 比例是**固定的**（不是 per-slide 可調）：

| Layout | 實際比例 |
|---|---|
| `image:right`（預設） | 文 ≈ 35% · 圖 ≈ 65%（圖為主角） |
| `image:left` | 圖 ≈ 65% · 文 ≈ 35%（圖為主角） |
| `image:top` | 圖佔內容區上方 ≈ 52% |
| `image:split` | 左半全高圖 · 右半文字 |

選 layout 時用這個對照，而不是假設可以任意調 40/60：

- 圖片是主角 → `image:left`、`image:top`、`image:split`、或 `image-full`
- 文字略多但仍要大圖陪襯 → `image:right`（圖仍約 65%）
- Product / UI showcase → 優先 `image:top`／`image:split`／`image-full`，screenshot 必須可辨識

對 UI screenshot：
- 必須大到可辨識主要介面結構。
- 不要把重要 UI 縮成裝飾性小圖或塞進小卡片。
- Builder **不支援**自由 annotation／callout badge——說明請用 bullets／paragraphs。
- 若 screenshot 本身就是故事，優先 `image:top`、`image:split` 或 `image-full`。

### statement（敘事強調頁）

用於 narrative pivot、重大結論、問題→解法轉場，或 dense slides 之間的 visual reset。與 `quote` 不同：`statement` 不需要出處，內容是簡報本身的主張。

```
┌─────────────────────────────────────────────────┐
│ SMALL EYEBROW                                   │
│                                                 │
│ The workflow isn't                              │
│ the problem.                                    │
│                                                 │
│ The handoffs are.                               │
│                                                 │
│                         short supporting text   │
└─────────────────────────────────────────────────┘
```

| 欄位 | 說明 |
|---|---|
| `eyebrow` | 小型分類 / context label（選填）；Markdown 可用 `**eyebrow**`／`**眉標**` |
| `title` | 主張，通常 1–3 行，36–48pt |
| `subtitle` | 短 supporting text（選填，建議） |
| `paragraphs` | 若未給 `subtitle`，會取第一段作為 supporting text |
| `dark` | `true` 可作高強度轉場 |
| `notes` | 講者備註 |

**使用規則：**
- 適合重大結論、敘事轉折、problem → solution pivot、章節中的視覺 reset。
- 不要拿來承載多項資訊。
- 大量留白是預期行為。
- `quote` = 引言 / 有 attribution 的主張；`statement` = deck 自己的敘事主張。

## Logo 與品牌元素的繼承機制

品牌 logo 和背景裝飾圖是放在**各個 layout 的 XML 裡**，不在 master 也不在個別投影片上。
當 `build_deck.py` 用 `strip_template_slides` 移除樣板的 13 張範例投影片時，layout 的 XML
（含其圖片 rel）完整保留，所以 logo 透過 layout 繼承到每一張新投影片上。

公司樣板的 logo 分佈：
- `image4.emf`（EMF 向量 logo）：出現在 Cover、Agenda、Content Heading、Title、Thank you 等
- `image6.png`（頁尾小 icon）：出現在 Agenda、Content Heading 等
- 底圖照片、漸層色塊：各自放在對應的 layout

`verify_deck.py` 在 package 層級會主動驗證「每個 layout 的 rel 指到的媒體檔案確實存在
於 zip package 裡」——若遺失會報硬錯誤，不會讓空白 logo 悄悄出現在輸出裡。

### 推薦風格

```
這一頁是什麼？
│
├─ 封面 ──────────────────────────────────────── cover
├─ 段落分隔 ───────────────────────────────────── section
├─ 內容頁
│   ├─ 要點 / 敘述 / 表格 / 圖表（通用）──────── content / content:standard
│   ├─ 主論點 + 次要支援（非對稱）──────────── content:editorial
│   ├─ 單一焦點句（非 big_number/quote）───── content:spotlight
│   ├─ 關係 / 架構（cards hub+spokes）─────── content:diagram
│   ├─ 圖表敘事（chart + insight）─────────── content:data-story
│   ├─ 並列兩個選項或面向 ─────────────────────── two-column
│   ├─ 文字＋圖片
│   │   ├─ 圖在右（預設，圖約 65%）──────────── image / image:right
│   │   ├─ 圖在左（圖是主角）─────────────────── image:left
│   │   ├─ 圖在上（截圖＋條文）───────────────── image:top
│   │   └─ 全版沉浸（無標題列）────────────────── image:split
│   ├─ 單張大圖 ────────────────────────────────── image-full
│   ├─ 卡片格
│   │   ├─ 等權重（自動網格）──────────────────── cards / cards:2-col / 3-col / 4-grid
│   │   ├─ 主次分明 ─────────────────────────── cards:bento / cards:featured
│   │   ├─ 圖示為主視覺 ──────────────────────── cards:icon
│   │   ├─ 步驟 / 排名（橫向卡）──────────────── cards:number
│   │   ├─ 流程步驟（直式）──────────────────── cards:steps
│   │   └─ 截圖 / 產品照 ──────────────────────── cards:image
│   ├─ 有出處的主張 / 關鍵句 ────────────────────── quote
│   ├─ 單一大指標（視覺衝擊最大）────────────────── big_number
│   ├─ 敘事轉折 / 重大結論 / 視覺 reset ───────────── statement
│   ├─ 時間序列 / 里程碑 ────────────────────────── timeline
│   └─ 純表格資料 ────────────────────────────── table
└─ 結尾（具體請求） ───────────────────────────── closing
```

### 兩種風格共同規則

- **每頁一個想法**，兩個想法就是兩頁。
- **標題要是結論**，不是主題。「Q3 流失率上升 4 個百分點」勝過「Q3 數據」。
- **標題只有一行**，不換行。約 20 個中文字是上限（依版面字級與框寬而異）。
- **數字的比較用圖表**，不要用要點列（聽眾不該在腦裡畫圖）。
- **單一數字不要畫圖表。** 數字本身是故事 → `big_number`；數字背後的結論是故事 → `quote`；數字只是證據 → 放進 conclusion-style title。
- **深底版面不放圖表**（`verify_deck.py` 硬錯誤）。
- **最多約 6 條要點**，每條約 12 字；超過就是文件了，移到備註或附錄。
