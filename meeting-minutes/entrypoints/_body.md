使用者要把錄音或逐字稿整理成會議記錄。

**預設：同一輪做完。** 同一則訊息通常有：音檔或 mp4、相關檔案（PPT、PDF、Excel）、參加者是誰與有幾位。
收到語音檔或螢幕錄影就轉錄（本機、含術語表錯詞修正）、存逐字稿、**自己 review 一次**、立刻寫會議記錄。
同一輪交出會議記錄，以及聽不清楚的 `.review.md`。人工表不必填。
螢幕錄影會多抽關鍵畫面；寫筆記前要 Read 那些 JPEG，也不要漏讀附上的 PPT／PDF／Excel。
不要轉完就停，也不要為了問參加者／會議類型而中斷。人數以使用者說的為準，不合就先 `relabel.py --speakers N`。
AI 從上下文確定的錯詞寫進 `.ai-review.md` 後**立刻跑 `learn.py` 進詞表**。
使用者丟來填好的 `.review.md`（或說已校對）也是先 `learn.py`。沒填的那張表不要拿去學。

## 第一步：讀取指示檔

```
__INSTRUCTIONS_PATH__
```

**用上面這個絕對路徑讀檔，不要用相對路徑猜，也不要憑印象執行。**
那份檔案是唯一指示來源，讀完整份再動手。裡面有幾件最容易被跳過的事：

1. **第 0 步先估轉錄時間。** 長錄音、Intel Mac 或 Windows 的較長錄音不要在這裡跑轉錄，
   印出終端機指令請使用者自己跑完再回來——不然使用者會在對話裡乾等半小時。
2. **第 3 步先勘查逐字稿品質。** 時間軸跳號、重複幻聽、音譯亂碼都要先看過。
   跳號累計超過總時長 10% 就在會議記錄裡註明，**仍繼續寫**，不要停下來問。
3. **第 5 步不要問完再寫。** 參加者、會議類型、連結從逐字稿推斷。
   **人名與人數以使用者這一輪提供的為主**，不要用推斷蓋掉；有名字就當主標（待辦寫 `**Joyie**：`）。
   使用者說有 N 位、逐字稿人數不同，先 `relabel.py --speakers N` 再寫。
   參加者列只寫這場有出席的人、每個人一行（`<br>`）：主持人標 `（主持人）`，其他人只寫名字，
   不要標「非主持人」或「講者 A」。只被提到、沒出席的人不要列進去。
   逐字稿已經用聲紋標好「講者 A／B」了，**機器只分得出是不同人、不知道名字**——
   沒有提供名單時，才從對話內容把代號對上真名，用在待辦／討論；並順手填逐字稿那張「誰是誰」表格。
   人數跟對話明顯不合（三個人互喊名字卻只標 2 人）就先跑
   `scripts/relabel.py <逐字稿> --speakers N` 重標，幾秒鐘，不用重新轉錄。
   同一輪寫好逐字稿和會議記錄；**對話只報路徑和需要人補的地方，不要貼全文。**
   若有 `<stem>.frames.md`，寫之前把列出的 JPEG 都 Read 過。
   這輪若附了投影片／PDF／Excel，也先讀，對得上的段落標來源（頁碼或表名）。讀不到不要猜數字。
4. **錯詞進詞表不必再問。** `.ai-review.md` 寫完、或收到人填好的 `.review.md`，立刻跑 `learn.py`。

## 第二步：依它的流程做完

範本有兩種，第 4 步會教你怎麼選：決議型會議用 `minutes.md`，
教學／交接錄音用 `training.md`。**選錯範本比格式醜嚴重**——教學型套決議型
會產出空的決議和空的待辦，看起來像沒開過會。

產出一律寫進本地 markdown。對話**不要**貼會議記錄或逐字稿全文，只說檔案在哪、哪裡需要人補。

## 使用者輸入

```
$ARGUMENTS
```

- 上面是空的 → 問使用者要處理哪個檔案。**不要**自己去 `audio_dir` 挑最新那個。
- 上面出現字面上的 `$ARGUMENTS` → 這個工具不支援參數替換，同樣直接問使用者。
