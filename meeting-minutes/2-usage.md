# 使用流程

這份說明怎麼把一場會議的錄音，交給 AI 整理成會議記錄。還沒安裝的話，先看 [1-install.md](1-install.md)。

> **AI 讀到這份檔案時：** 被叫來整理會議，細節以工具資料夾裡的 `INSTRUCTIONS.md` 為準。

---

## 整個流程一覽

1. **準備**：錄音檔、會議用到的簡報或表格、參加者名單
2. **交給 AI**：在 AI 對話框輸入 `/minutes`，附上上面三樣
3. **等它寫完**：AI 會自己轉逐字稿、自己檢查一次、寫出會議記錄
4. **打開會議記錄**：到桌面的「會議記錄」資料夾裡的 `minutes` 找檔案

第 4 步之後會多一張「聽不清楚的地方」的表，**可以不填**，不填也不影響會議記錄。

---

## 開始前：兩件事先想好

**這場會適合用嗎？**
錄音檔本身會留在你的電腦，不會上傳。但轉出來的逐字稿文字、螢幕錄影的截圖，會交給 AI 工具讀。所以**人事、薪資、法務、未公開財務**的會議不要用這個工具。

**錄音多長？**
太長的錄音直接丟給 AI，你會在對話視窗前乾等很久。先對照下表：

| 你的電腦 | 直接丟給 AI | 超過就改用〈[長錄音：先在終端機轉](#長錄音先在終端機轉)〉 |
| --- | --- | --- |
| Mac（Apple M 系列） | 約 60 分鐘以內（實測 38 分鐘的錄音約 2 分鐘轉完） | 超過 60 分鐘 |
| Mac（Intel） | 約 10 分鐘以內 | 超過 10 分鐘（60 分鐘的錄音可能要轉 60–90 分鐘） |
| Windows | 約 5 分鐘以內 | 超過 5 分鐘（60 分鐘的錄音可能要轉 1–3 小時，看電腦） |

不確定也沒關係：AI 會先看錄音長度，太長的話它不會自己轉，而是給你一行指令，請你先在終端機轉好。

---

## 第 1 步：準備要交給 AI 的東西

| 準備什麼 | 說明 |
| --- | --- |
| **錄音或螢幕錄影**（必要） | 錄音可以是 `.m4a`、`.mp3`、`.wav` 等。如果會議中有人分享螢幕、指著畫面講，請給**螢幕錄影 `.mp4`／`.mov`**，AI 才看得到畫面上的路徑和檔名。 |
| **會議用到的檔案**（有就給） | 簡報、PDF、Excel 等。AI 會拿來對照，把專有名詞寫對，並標出內容來自第幾頁。沒有就不用。 |
| **參加者名單和人數**（強烈建議） | 例如「3 位：Joyie（主持人）、Zoe、Allen」。AI 聽得出有幾個不同的聲音，但**不知道誰是誰**，你給名單它才能把待辦寫到正確的人身上。 |

錄音建議先放進桌面「會議記錄」資料夾裡的 `audio`，方便之後找。放別的地方也可以，只要告訴 AI 路徑。

**收音小提醒：** 用會議室麥克風或手機錄，盡量不要用筆電內建麥克風。收音太差的錄音，再好的模型也救不回來。

---

## 第 2 步：在 AI 對話框交給它

`/minutes` 是安裝時加進 AI 工具的一個指令，意思是「幫我把這場會議整理成會議記錄」。

**在 Cursor 或 VS Code 裡：**

1. 打開 AI 對話面板，切到 **Agent** 模式（AI 才能在你的電腦上轉錄）。
2. 在對話框輸入 `/`，從跳出的清單選 **`minutes`**。
3. 在**同一則訊息**裡接著寫上檔案和參加者，像這樣：

   ```
   /minutes
   音檔：~/Desktop/會議記錄/audio/2026-09-11-設計評審.m4a
   投影片：~/Desktop/設計評審.pptx
   表：~/Desktop/報價.xlsx
   參加者 3 位：Joyie（主持人）、Zoe、Allen
   ```

4. 按 Enter 送出。

不想打路徑的話，可以直接把檔案從 Finder（Windows 是檔案總管）拖進對話框。Windows 的路徑長得像 `C:\Users\你的名字\Desktop\會議記錄\audio\設計評審.m4a`，照貼就好。

**在 Codex 或 Claude Code 裡：** 一樣在對話框輸入 `/`，從清單選 `minutes`（Codex 可能顯示成 `prompts:minutes`），後面接同樣的內容。

AI 要執行終端機指令（例如轉逐字稿）時會先問你，按「Run」／「Accept」讓它繼續。

---

## 第 3 步：等 AI 做完

送出後不用再說「繼續」，AI 會一口氣做完：

1. **把錄音轉成逐字稿。** 在你的電腦上轉，錄音不會上傳。以前校對過的錯字會自動套用。
2. **自己檢查一次逐字稿。** 拿你給的名單、簡報、表格（和螢幕錄影的畫面）對照，把明顯聽錯的詞改掉，並記下來讓下次更準。
3. **寫出會議記錄。** 它會自己判斷這是「開會討論」還是「教學／交接」，選對應的格式。

做完後，對話裡**不會貼全文**，只會告訴你：檔案存在哪裡、哪些地方需要你補（例如聽不出名字的講者）。

---

## 第 4 步：打開會議記錄

檔案都在桌面「會議記錄」資料夾裡的 `minutes`。以「9/11 開的會、9/15 才整理」為例：

| 你會看到 | 位置 | 檔名的日期 |
| --- | --- | --- |
| **會議記錄**（主要看這份） | `minutes/2026-09-11-設計評審.md` | 開會那天 |
| 逐字稿 | `minutes/2026-09-11-設計評審/2026-09-15-設計評審.md` | 整理那天 |
| 聽不清楚的地方（選填） | 同一個資料夾的 `…設計評審.review.md` | 整理那天 |
| AI 自己改了哪些詞 | 同一個資料夾的 `….ai-review.md`（有改才會有） | 整理那天 |
| 螢幕錄影的截圖 | 同一個資料夾的 `….frames.md` 與 `.frames/`（只有給 mp4／mov 才有） | 整理那天 |

會議記錄用開會日，逐字稿用整理日，是刻意的：同一場的所有檔案都收在同名資料夾裡，不會搞混。

`.md` 檔可以用 Cursor 或 VS Code 打開閱讀，按右上角的預覽看排版後的樣子。

---

## 會議記錄長什麼樣

AI 會依錄音內容挑一種格式：

| 格式 | 適合 | 內容順序 |
| --- | --- | --- |
| **決議型** | 多人開會、有指派工作、有拍板決定 | 總結 → 待辦 → 決議 → 還沒決定的事 → 討論細節 |
| **教學型** | 一個人示範操作、螢幕分享、工作交接 | 總結 → 之後怎麼做 → 注意事項 → 教學細節 |

**挑錯了就直接跟它說**，例如「這是教學，請用教學型重寫」。挑錯很明顯：教學錄音套成決議型，操作步驟會變成一句「討論了 A 和 B」，重要內容都不見了。

幾個你會看到的寫法：

- **討論細節**：每個主題底下先列結論，再列「提問重點」——誰問了關鍵問題、誰做了決定，之後要追問時知道找誰。
- **來源標註**：內容對得上你給的簡報或表格時，標題後面會寫 `（投影片第 4 頁）`。看不到頁碼就寫投影片標題，不會亂猜。
- **⚠️ 標記**：AI 聽不清楚、又不敢亂猜的地方，會留一行這樣的提示：

  ```
  > ⚠️ 此處逐字稿不清楚（去聽錄音 00:23:50）：這邊要改成那個…
  ```

  這不是壞掉，是刻意留給你確認的。用播放器跳到括號裡的時間聽一下就好。指令、檔案路徑聽不清楚時一定會標，不會編一個給你。

## 參加者或人數不對時

**參加者那一列**只會列有出席的人，一人一行，主持人會標 `（主持人）`。錄音裡被提到、但沒來開會的人不會列進去。

**沒給名單時**，AI 會從對話內容推誰是誰（例如有人喊「Allen 你覺得呢」）。推不出來的會標出來請你補，但不會因此停下來不寫。

**AI 分出來的人數不對時**（例如明明 3 個人，它只分出 2 個聲音），最簡單的做法是直接在對話裡跟它說：

```
其實有 3 位，請重新分講者再更新會議記錄
```

它會在幾秒內重新分，不用整段重轉。你已經填好的名字不會被蓋掉。幾乎整場只有一個人講的教學，就說「只有 1 位」。

兩人同時講話、或只回一句「對啊」的地方，本來就很難分準，以你的記憶為準。

想自己在終端機改的話（`<逐字稿>` 換成逐字稿的完整路徑）：

- Mac：

  ```bash
  ~/Desktop/meeting-minutes/.venv/bin/python ~/Desktop/meeting-minutes/scripts/relabel.py "<逐字稿>" --speakers 3
  ```

- Windows（PowerShell）：

  ```powershell
  & C:\meeting-minutes\.venv\Scripts\python.exe C:\meeting-minutes\scripts\relabel.py "<逐字稿>" --speakers 3
  ```

工具資料夾不在上面的位置的話，換成你的路徑。

## 聽不清楚的表（選填）

`.review.md` 是 AI 最沒把握的幾十句，不是整份逐字稿。**完全不填也沒關係。**

填了的好處是：你改過的詞會記進全隊共用的詞彙表，**之後所有人**轉錄時都會自動改對。實測專有名詞的正確率從 36% 提升到 82%，比換更大的模型還有效。

想填的話：

1. 用 Cursor 或 VS Code 打開那份 `.review.md`。
2. 在「應該是」那一欄填上**正確的整句**。聽不出來、或本來就是對的，留空。

   | 時間 | whisper 聽到的（⟦⟧ 是可疑處） | 應該是 | 為什麼被挑出 |
   | --- | --- | --- | --- |
   | `00:23:50` | 我用的是⟦鳳猴身⟧ | 我用的是 Font Awesome | 未知英文 |

3. 存檔，把這個檔拖回原本的對話，或跟 AI 說「已校對」。它會把修正記進詞彙表。

要讓同事也用到你的修正，在工具資料夾把詞彙表同步出去（`git push`）。沒有 push 的話，修正只留在你這台電腦。

## 長錄音：先在終端機轉

錄音超過前面〈錄音多長？〉的建議長度時，先自己在終端機把逐字稿轉好，再交給 AI 寫會議記錄。這樣轉錄的時間你可以去做別的事，不用盯著對話視窗。

1. 打開終端機，貼上（把錄音路徑換成你的）：

   **Mac**：打開「終端機」（在「應用程式 → 工具程式」裡）

   ```bash
   cd ~/Desktop/meeting-minutes
   ./bin/transcribe ~/Desktop/會議記錄/audio/2026-09-11-設計評審.m4a
   ```

   **Windows**：從「開始」選單搜尋並打開「PowerShell」

   ```powershell
   cd C:\meeting-minutes
   .\bin\transcribe.cmd "C:\Users\你的名字\Desktop\會議記錄\audio\2026-09-11-設計評審.m4a"
   ```

   錄音路徑可以直接把檔案拖進視窗貼上。工具資料夾不在上面的位置的話，`cd` 那一行換成你的路徑。

2. 跑完後，最後一行會印出「完成：」和逐字稿存在哪裡。Windows 轉 1 小時的錄音可能要 1–3 小時，視窗開著去做別的事就好，不要關掉它。
3. 照〈第 2 步〉交給 AI，只是把「音檔」換成**逐字稿的路徑**，簡報、表格、參加者一樣附上。AI 看到是逐字稿就會跳過轉錄，直接檢查、寫會議記錄。

---

## 輸入 `/` 找不到 `minutes` 時

1. 先試：完全結束你的 AI 工具（不是只關視窗）再開。
2. 還是沒有：在工具資料夾的終端機執行 `./install.sh --update-entrypoints`（Windows：`.\install.cmd --update-entrypoints`），再重開 AI 工具。
3. 急著用：照〈長錄音：先在終端機轉〉把逐字稿轉好，然後打開工具資料夾裡的 `INSTRUCTIONS.md`，把全文貼進 AI 對話框，後面接著附上逐字稿路徑、相關檔案和參加者。

---

## 這個工具不做的事

- 不會幫你管理待辦進度，會議記錄裡的待辦只是紀錄
- 不會同步 Figma 或設計檔
- 不能在開會當下即時轉錄，要錄完再整理
- 不會記住誰的聲音。每場都要重新告訴它參加者是誰
